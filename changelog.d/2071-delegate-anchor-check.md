- Fix: a delegated child no longer loses a new row when its compression boundary is missing (a failed pre-compaction store, a failed boundary record, or a concurrent store) and a later row repeats the last stored row (#2071). The stored-tail anchor now resumes only when every row in front of it is stored in the child's lineage or is one of the last compaction's own outputs. Rows in front that are neither are stored with the rows after the anchor, with a warning that says how many there were. A head that the host rewrote outside LCM's compaction is therefore stored once, so no row behind it is skipped. The record of compaction outputs lives in the process: after a restart, a delegated child's compacted head is stored once. A new row whose content and role equal an older stored row's still cannot be told apart from it.
