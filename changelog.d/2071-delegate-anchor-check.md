- Fix: a delegated child no longer loses a new row when its compression boundary is missing (a failed pre-compaction store, a failed boundary record, or a concurrent store) and a later row repeats the last stored row (#2071). The stored-tail anchor now resumes only when every row in front of it is stored or is one of the last compaction's own outputs; otherwise the counted fallback runs, with a warning that says how many rows were unaccounted. A head that the host rewrote outside LCM's compaction is now stored once, so no row behind it is skipped. The record of compaction outputs lives in the process: after a restart, a delegated child's compacted head is stored once.
