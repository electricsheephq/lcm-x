- Fix: after a restart, when the resume point falls between a stored tool call and its stored result, the re-sent result is no longer stored a second time (#2163). It is skipped only when the stored copy of that call is followed directly by an identical stored result that no earlier row accounts for, and the stamps agree. A result without that evidence is stored as before, so a host that reuses tool-call ids cannot lose a new result. Adds a strict-xfail pin for the known #2172 limit (a new call and result that repeat a pair compacted out of the view).
