- Fix: When the host changes its list before the ingest cursor and the audit also misses a row below the cursor, moved tool-call rows and their results are now stored (#2455). This holds within a presence window of 10,000 stored rows, 15 million bytes of stored text (including tool-call text) and 10,000 stored tool-call entries, across the session, its verified compression ancestors and its recorded rotation predecessors (all three limits must hold), and only for the standard tool-call format (each stored call entry an object with a text id and text arguments). These keep main's positional result, each a named limit under #2467 with a strict-xfail test: a moved tool row on a turn where the audit misses no row (`tests/test_2466_presence_round5_gate.py`); a scope holding any other tool-call format (`tests/test_2466_presence_tool_shape.py`); a call whose arguments LCM-X externalizes at ingest (an inline data URI with 256 or more base64 characters, a run of 4,096 or more base64-alphabet characters, or a line-wrapped base64 block), which reads as a reused id (`test_dangling_call_with_a_base64_argument_then_its_result_below_the_cursor`); and a session whose history, counting its compression chain and recorded predecessors, is larger than the window (10,000 rows, 15 MB of stored text or 10,000 tool-call entries), which gets main's result for class A (`test_2455_past_presence_window_moved_call_is_stored_named_limit`). Tool ids match exactly, including non-ASCII ids; an id stored anywhere in that scope counts as stored; a new call is stored only with the results the view shows for it, and a new result only with its call; a reused id (#2172) keeps main's result. The window is sized in SQL before any row loads and the audit loads no payload file, so its added wait under the write lock stays within 150 ms at each limit (measured on a 14-core machine at load below 7). The limit is logged at INFO once per session per process. A replaced reply (#2116) is not covered here and moves to v0.30.x (#2467). If a presence read fails, ancestry cannot be verified with state.db present, or a rotation predecessor write failed in this process, the audit keeps its own finds, leaves the other rows as replays and logs a warning.
