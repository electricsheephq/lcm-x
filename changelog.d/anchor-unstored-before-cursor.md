- Fix: When the host changes its list before the ingest cursor, moved tool-call rows, results and replaced replies are now stored within a presence window of 10,000 stored rows across the session, verified ancestors and recorded rotation predecessors (#2116, #2455). Tool ids match exactly, including non-ASCII ids. Stored copies are counted before adding rows; a result is never added without its call. Past the window, these rows stay positional replays as on main, a named loss limit to be fixed in v0.30.x. If a presence read fails, the audit keeps its own finds, leaves the other rows as replays and logs a warning.
