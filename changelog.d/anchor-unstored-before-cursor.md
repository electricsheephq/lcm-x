- Fix: When the host changes its list before the ingest cursor, a row in front of the resume point (a tool-call row or a replaced reply included) is now stored unless it is bound, matched to a stored row or a compaction output; before, it was taken as a replay by position and never stored (#2116). This holds while the session and each compression ancestor hold fewer stored rows than the prefix audit reads (64, or twice the number of rows from the end of the unchanged prefix to the cursor when that is larger). When any of them holds that many or more, the previous behaviour is kept, which is listed as a known limit (#2455). The audit line is now a WARNING naming the reason and the count.
