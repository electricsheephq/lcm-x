- Changed: Known limits, messages that may not be saved (each planned to be fixed in v0.30.x):
  - #1525: if the host sends a shortened conversation by itself (for example an undo followed by a compression request that compacts nothing) and then new messages, those new messages can be taken as already saved and are not stored. Which hosts do this is not established.
  - #2124: after a restart and a compaction, on a host that sends only new messages, a message whose text appears more than once in the session can be saved fewer times than it was sent. Hosts that send full history, as Hermes does, are not affected.
  - #2172: after a cold restart, a new tool call and its result that exactly repeat an earlier pair already compacted out of view can be taken as a replay and not saved. Only hosts that reuse tool-call ids are affected.
  - #7: when the host merges or replaces a message before LCM-X's saved position, a new message without a timestamp can be dropped. In the widest case, a view without timestamps that replaces every saved message at the same length saves none of them.
  - #2116: a host message replaced below LCM-X's saved position is treated as a replay and is not saved while the session is running.
  - #1428: when only a message's id changes, behind a merged system block that did not change, the replacement can be lost once the session's saved proof has been used.
  - #1519: a new message with the same text as an earlier one, arriving on a timestamp LCM-X recorded for that earlier one, is not saved once the original view has gone.
  - #1563: an in-place edit of an earlier message, sent inside a shorter view of the conversation, is never saved. This was already the case in v0.27.0.
  - #1837: in cold mode, a retried tool result whose only change is a new message id is dropped.
  - #2377: after a restart, a new tool call and result identical to an earlier saved pair can be taken as a replay and not saved. When the restart follows a saved rewrite of the earlier result, the earlier call can also be saved again next to the rewritten result.
  - #2110 and #2418: a user message that begins with text the host itself uses as scaffolding (a preserved-objective or task-list prefix, or a quoted summary), for example because it was pasted, can be skipped in a session not yet compacted, under an older proof version, or after a stale proof is retired. The task-list prefix can be skipped in every proof state.
  - #2422: in a delegated sub-agent session with many identical user messages, one occurrence may not be saved.
  - #2440: in a delegated sub-agent session, if saving fails just before the host compacts (for a reason other than a busy database), the compacted messages are lost. Their summary is saved and is their only record. A busy database skips the compaction instead.
  - #1037: after a cold restart, a new message with the same text in the same second as an earlier one, but under a new platform id, is taken as that earlier message and not saved.
  - #2419: a running session that receives a view starting with a tool call, which does not extend the previous view, saves nothing from it. No host is known to send such a view.
  - #2452: LCM-X's check of the conversation before its saved position does not examine tool messages. A tool call and result replaced before that position are lost, and a pair inserted there saves the result without its call. Since #2466 these tool messages are saved when the same save also finds a missed text message before that position, for standard tool calls, in sessions whose history is within 10,000 messages and 15 MB of text.
  - After a session end that hits a busy database with no later save, two or more messages whose host timestamps conflict with saved copies can be lost, as in v0.29.2.
  - After a busy session end, an undone-and-resent message is kept pending, counted and reported at exit rather than saved; only a host resume of that session recovers it. On a host that exits without a clean shutdown (the Hermes gateway until its upstream fix), the pending save is never retried, and only the warning logged when it was queued names the session.
- Changed: Known limits, extra copies with nothing marking them (no message is lost; each planned to be fixed in v0.30.x):
  - #2468: when a tool call was not saved at its turn, a later save that brings the full history (typically after a restart or a rebind) saves the call once and its tool result a second time.
  - #2461: when the host points an existing session at a new routing key (for example a CLI handoff, or a /resume from another room), the session's next turn saves its whole history again under the new key.
  - #2463: after a compression hands a session to a child that LCM-X cannot verify, a host insertion before the saved position saves the parent's last prompt and reply again under the child.
  - #2374: after a save fault that persists past its retry, the last message can be saved a second time.
  - #2440: in a delegated sub-agent session, after a failed save just before compaction, the compacted head can be saved once more.
  - #503: after a repeated user message goes through two recovery fits and the host restarts, that user message can be saved once more.
  - #1961: a running session can save a duplicate after the host merges LCM-X's summary into a user message.
  - #1674: after a restart, replayed messages without a timestamp can be saved again.
  - #2203: a view without timestamps rewritten after a cold retry, or by a resumed session, can be saved again.
  - #849: after a restart before the reply, the unanswered prompt and the next one can be saved as one combined message next to the next prompt's own copy.
